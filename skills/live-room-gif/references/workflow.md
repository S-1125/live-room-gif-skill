# 直播间 GIF 工作流

## 需求采集

制作前尽量确认以下信息：

- 投放位置：直播间贴片、商品卡、公告条、活动页或其他位置。
- 画布尺寸和比例。
- 必须保留的固定元素。
- 需要变化的文字、图片、价格、库存、倒计时或贴纸。
- 参考 GIF 或静帧风格。
- 每段停留时长、总时长、循环方式。
- 是否透明、是否需要无缝衔接、是否有文件大小限制。
- 输出数量：单个成品、批量版本或多个尺寸。

用户没有提供但可以从素材推断的信息，直接采用并记录假设；只有会改变制作方向的缺失项才提问。

## 动画设计

先写帧计划，再开始渲染：

1. 固定层：商品、底图、边框、标题等不变内容。
2. 变化层：文案、价格、图片或其他状态。
3. 节奏：每个状态停留多少毫秒，入场和退场占多少帧。
4. 循环：末帧回到首帧时是否跳变；需要淡入淡出时是否使用中间帧。
5. 可读性：长文案、最大价格位数和多语言文本都要预先留宽。

GIF 没有音频。需要声音时，另行建议视频格式。

## 审核

至少提供以下检查材料：

- 可播放的 GIF。
- 全部帧的缩略拼图。
- 透明素材的棋盘格预览。
- 帧数、单帧时长、总时长、尺寸和循环方式。
- 逐帧 PNG 目录或压缩包。

审核重点：

- 文案是否与用户原文完全一致。
- 位置、字号、留白和视觉重量是否接近参考。
- 速度是否可读，循环是否突兀。
- 边缘是否有多余黑边、白边或旧文字残影。
- 长文案是否越界，短文案是否显得过小。

## 版本与反馈

- 用户要求“快一点”“慢一点”时，保留上一版并新增速度版本。
- 用户要求“背景透明”时，重新检查 alpha，而不是只更换预览底色。
- 用户指出位置或字号问题时，先调整参数并做小样，不要立即重构整个脚本。
- 用户明确认可后，将参数和验证结果写入案例登记。

## 案例晋级

只有同时满足以下条件，才把一次性实现升级为稳定案例：

1. 用户明确审核通过。
2. 至少完成一次真实文件回读验证。
3. 可复用步骤能被描述为明确约束，而不是“看起来更好”。
4. 该做法不会覆盖或破坏已有案例。

稳定案例优先保留专用脚本；尚不稳定的案例保留在案例登记中，仅记录问题与临时参数。
